## ¿Qué validar?

1. **Deseabilidad** — ¿El usuario tiene este problema y le interesa tu solución?
2. **Usabilidad** — ¿Entiende cómo usar el producto sin demasiada explicación?
3. **Valor** — ¿El MVP le ayuda a resolver una necesidad concreta?

---

## Hipótesis Principal

Estructura sugerida:

> Creemos que \[tipo de usuario] tiene el problema de \[problema específico] y que nuestro MVP le ayudará a \[resultado esperado] mediante \[solución principal].

## KPIs de Testing

| Categoría | KPI | Meta sugerida |
|-----------|-----|---------------|
| Adquisición | Usuarios invitados | 10-20 |
| Adquisición | Usuarios que probaron | 5-10 |
| Activación | % que completa acción principal | 50%-70% |
| Usabilidad | % que completa tarea sin ayuda | 50%+ |
| Usabilidad | Tiempo para completar tarea | <5 min |
| Valor | Calificación de utilidad | 4/5+ |
| Satisfacción | Intención de volver a usarlo | 50%+ |
| Feedback | Insights accionables | 5-10 claros |

---

## Cómo preparar una sesión

1. **Definir perfil del usuario** — que se parezca a tu usuario objetivo
2. **Preparar escenario de prueba** — instrucción breve, sin guiar
3. **Observar antes de intervenir** — dónde se detiene, qué no entiende
4. **Preguntar después** — qué crees que hace, qué fue confuso, lo usarías de nuevo

## Priorizar feedback

- 🔴 **Crítico** — Bloquea el uso del MVP
- 🟡 **Importante** — Genera fricción, no bloquea
- 🟢 **Futuro** — Valioso pero no urgente

---

## Reporte de testing (actividad sugerida)

Incluir:
1. Hipótesis principal
2. Perfil de usuarios testeados
3. Número de usuarios
4. Flujo evaluado
5. KPIs definidos
6. Resultados
7. Principales fricciones
8. Feedback más relevante
9. Cambios realizados
10. Siguiente versión del MVP
